根据下面要求生成代码：

1. 环境：

云端：WSL+Ubuntu24+uv
手机端：Android 13+Google Chrome

2. 基本要求：

（1）项目要求有README.md文件，每次更新均同时更新README.md文件
（2）项目要求有pyproject.toml文件，每次更新均同时更新pyproject.toml文件
（3）同时给出stey-by-step运行步骤
（4）云端可以全套运行，包括命令行的客户端；手机端需要合理设计，只把交互逻辑、用户登录授权信息等放在手机端

3. 项目整体功能说明：

（1）定期获取当前携程、淘宝、京东、抖音商城等平台的优惠券信息（金额、优惠券类型、优惠券有效期等）；然后从中挑选中机票相关的优惠券；
（2）用户输入机票目的地和预计出发时间，系统会根据用户输入的条件以及个人本地记忆文件中的信息得到用户偏好等相关数据并组成成上下文
（3）根据用户上下文，结合对机票价格的预测分析，综合考虑如何满足全网最低价下的机票购买需求，并提示用户是否需要购买
（4）用户确认购买后，系统会根据用户输入的条件以及个人本地记忆文件中的信息，从当前平台获取优惠券信息，然后从中挑选中机票相关的优惠券；
（5）用户可以根据优惠券信息，选择最符合自己需求的优惠券，最后确认购买
（6）用户购买完成后，系统会记录用户购买信息，包括购买时间、购买金额、购买优惠券等进入本地记忆文件中；同时给手机增加一个出发通知，提示用户在指定时间出发

4. 项目模块设计

（1）信息获取智能体：（a）定期获取各大平台机票价格；（b）负责获取当前携程、淘宝、京东、抖音商城等平台的机票优惠券信息（金额、优惠券类型、优惠券有效期等）；（c）所有数据并记录在本地md数据库文件中，一个记录优惠劵，一个记录机票价格变化
（2）机票价格预测智能体：负责根据用户输入的机票目的地和预计出发时间，结合对机票价格的预测分析，综合考虑如何满足全网最低价下的机票购买需求，最后提示用户是否需要购买
（3）数据检查智能体：负责检查本地md数据库文件中的数据是否完整，是否有缺失值，是否有冲突和歧义等问题；每天凌晨1点运行一次
（4）交互智能体：负责与用户进行交互，包括用户输入、用户确认、用户选择优惠券等操作；负责根据用户输入的条件以及个人本地记忆文件中的信息；以及获取优惠价并执行购买操作
（5）主智能体：负责管理上下文和执行步骤，协调其他智能体的工作，确保系统正常运行

5. 从用户视角整体执行流程说明：

（1） 主程序启动的时候，进入的是主交互界面，询问用户需要订什么机票。可以适当闲聊，但主要目的是澄清用户的意图，获取购买的品类的预期（如机票，获取地点，时间，偏好等）

（2）一旦所需要信息齐全后，即可启动sub-agent进行盯盘预测最佳购买时间点。主交互程序返回继续和用户聊天。除非用户明确说要退出否则依旧处于等待交互状态

（3） 后台sub-agent判断有合适的优惠劵，以及合适和购买时机的时候，提示相关决策选项，并与用户交互获取用户的决策选择结果继续执行

（4） 当最近购买商品（如机票）时机来临后，提示相关选项给用户决策，并进入购买流程。在购买流程中，可能选择某一个单价最低（结合优惠劵）的平台进行购买，这时候需要提示用户并获取平台的登录信息。该信息保留到特定的凭据md文件中，供下次使用
